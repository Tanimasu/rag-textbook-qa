## 界面和操作体验

- Streamlit 的失败回答立即提供“重试本题”。重试使用原问题、教材和参数，历史记录保留；普通页面刷新不自动重新调用模型。
- 参考来源保留完整的实际片段和原文换行，按资料自身的引用编号显示，去掉缺失分数伪装成 0.000 的显示。长片段可在卡片内滚动核对。
- 回答完成后重新展示已保存对话，欢迎提示消失，输入框位于回答之后。实际浏览器已检查失败重试、来源展开和输入框位置。
- 缩小回答标题区域的空白，窄屏状态卡保留三列并调整内边距，减少提问前的滚动。
- 等待状态随实际流程变化：检索教材、检索完成等待模型、接收回答，回答结束后收起状态提示。
- 公开问答页的输入框有明确的辅助标签和焦点提示，手机上使用简短占位提示，键盘说明与字数限制放在输入框下方。反馈保存说明可以展开查看。Streamlit 长原文区域支持键盘聚焦和滚动。

浏览器预览使用固定回答服务，仅监听本机，不调用模型或 Worker。交互回归覆盖原参数重试、页面刷新不重复调用、真实来源而非未发送候选、引用编号和片段末尾内容。

## 评测调用用量留档

`evaluate-generation` 为每次生成和评判 HTTP 尝试追加 `calls.jsonl`，包含时间、阶段、模型、请求散列、结束原因和输入/输出/推理/缓存 token。失败和重试也留记录；服务商没有提供的用量记为未知。日志不保存提示词、答案、思考文本或服务商错误原文。

用量无法写入时，取消尚未启动的评测任务，并停止后续阶段。评判响应即便是合法 JSON，只要未正常结束也不计入质量分。因接受结果的条件改变，评判协议升为版本 5；旧协议目录不能原地续跑，历史记录不补写新版本。
