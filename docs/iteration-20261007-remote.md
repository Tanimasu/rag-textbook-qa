## 复现并修复传输中断

发现远程客户端只捕获建立连接的错误与超时，响应读取期间的 `IncompleteRead`、连接重置或
远端直接断开会原样抛出。因此即使已启用查询本地回退，也不会执行回退。
另外，截断的 401 错误正文会掩盖认证错误；NaN / 无穷大超时值会通过配置检查。

新增四项回归方法在修复前失败，修复后通过。修复包括：

- 将响应读取中断归为瞬时故障，丢弃部分结果，允许查询回退重算整个输入；
- 根据 HTTP 状态保留认证 / 模型错误分类，即使错误正文不完整也不触发回退；
- 完整或截断的 HTTP 错误响应均显式关闭；
- 环境配置与直接构造客户端时，都在连接前拒绝非有限或非正的超时值。

新增 `scripts/check_remote_transport.py` 使用真正的回环 HTTP、无模型 Worker：150 个重排输入
分成 128 / 22，第二批截断后本地重算全部 150 个；恢复后下一次调用重新使用远程。
截断的 401 / 409 和完整但格式错误的响应均不回退。检查已加入六种系统 / Python 组合的 CI。
实际结果为同目录 `transport.json`，这是传输故障模拟，不是 CUDA 性能数据。

## 浏览器流式响应

继续在实际页面中复现两类问题：

- CRLF / CR 换行的合法事件无法解析，结束后被误报为连接中断。把整个响应逐字节切分时同样失败；
- `result` 或终止 `error` 已经显示，只要连接还保持打开，发送按钮就一直禁用。
  页面也继续读取后面的内容，完整结果可能被后续片段或网络错误覆盖。

[HTML 标准的 SSE 解析规则](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)
允许 LF、CRLF 和 CR。修复按解码后的片段归一化换行，保留跨片段 CRLF 状态；中文 UTF-8
继续使用流式解码。收到终止事件后取消读取并恢复表单，完整结果保留为最终显示内容。
缺少终止事件的连接中断仍保留部分文本并提供重试，用户主动停止流程不变。

新增四项浏览器回归方法（五个场景）均在修复前失败，修复后连同原六项测试全部通过。
本机使用现有 Chrome；HTTP 后端为隔离的测试替身，逐字节边界使用浏览器原生 Response 流保证。
不调用回答模型，不把页面测试当作生成质量验收。检查继续由现有 Chromium CI 执行。

## 防止 SDK 放大重试次数

使用真实 SDK 和隔离的 503 响应复现：非流式设置 `retry=1` 应最多请求两次，实际请求六次；
流式没有项目层重试，实际仍请求三次。原因是 SDK 默认的两次重试叠加在项目重试之内。
默认非流式 `retry=2` 因此可能产生九次请求。

创建项目自有 SDK 时显式关闭 SDK 重试。非流式仍按传入的 `retry` 尝试，默认最多三次；
流式失败由用户重试。自定义注入的 SDK 仍由注入方负责配置。未完成回答不会因此重试。
回归方法在修复前两种情况均失败，修复后确认两次 / 一次；没有调用外部模型。

本机 Python 3.11 / 3.12 各 442 项测试通过，Ruff 与差异空白检查通过。
每日生成额度仍按生成操作计数；非流式内部重试、输出长度和服务商计费规则会影响实际费用，
它不是按人民币或美元设置的费用硬上限。

继续复现发现 401 / 422 也会被项目层重复请求三次。修复后永久 HTTP 错误立即失败；
408 / 409 / 429 和 5xx 仍允许在既定预算内重试。真实 SDK 的模拟响应检查确认 401 / 422
各一次且不等待，429 / 503 各最多三次；不完整的正常响应仍不重试。
本机 Python 3.11 / 3.12 各 443 项测试通过。迭代期间再次只读复核远程健康：
401 / 200、Windows / CUDA 与两个模型指纹仍匹配。

## 中文日志与写入失败后的续跑

发现已有的 JSONL 尾行恢复仅覆盖合法 UTF-8：写入恰好截断中文字符时，整文件解码失败。
另外，同一进程的一次部分写入失败会使下一条结果粘到坏尾行；缓冲内容在关闭时写盘失败，
内存仍会把这条记录计为已保存。

修复为逐行严格解码，损坏行保持原始字节并跳过，其他完整回答原样读取；不使用替代字符修补正文。
写入开始后保留“可能存在坏尾行”的状态，只有文件成功关闭才清除并登记内存记录。
后续追加会先分隔坏尾行，不修改此前的数据。序列化与必需键读取在打开文件前执行。

新增三项回归在修改前失败，修复后通过，覆盖中文半字符、完整行内非法字节、部分写入失败、
关闭时缓冲写盘失败，以及后续结果的重新加载。这里不宣称硬件断电持久性，也未重写历史日志。
本机 Python 3.11 / 3.12 各 451 项测试通过，Ruff 与差异空白检查通过。

再复现两种 JSON 文件发布失败：首次协议写到一半会留下无法续跑的冻结文件；更新报告写到一半
