# 普通问答15题验收（2026-09-14）

文中的 `artifacts/` 链接指向本地验收文件，不随源码推送；结论、参数和限制保存在本文中。
结论：接口调用稳定，但答案质量尚未全部通过。15次请求均成功并正常结束，未超时；逐题对照实际输入片段后，7题核心回答基本可用（其中2题有措辞建议），8题需要修正。其中7题存在生成时额外补充、错误推断或适用范围丢失，1题的关键证据已检索到却未进入上下文。

这是助手对复用开发题的教材依据审查，不是独立人工评测、RAGAS得分或整体准确率估计。一般知识上正确也不自动等于被本次引用支持；对原书陈述的忠实也不认证所有实际系统条件下均正确。

## 运行条件

- 五本教材各3题，共15题，全部来自dev；题目原文保持不变，未使用holdout。
- 答案接口：`api.siliconflow.cn`，模型 `deepseek-ai/DeepSeek-V4-Pro`；用户已明确授权本轮API调用。
- 本机MPS检索，embedding `BAAI/bge-large-zh-v1.5`，reranker `BAAI/bge-reranker-base`，Top-5、上下文2000字符。
- 关闭HyDE、查询分解、引用核对；已知冲突保护仍按普通流程启用，本轮选题未触发。
- 温度0.7、输出上限2000 token，与页面默认一致；60秒超时、无重试，每题一次。本轮采用非流式调用以记录结束原因与token，不测页面首字时间；远程Worker没有参与，因此不代表当前默认远程配置的延迟。
- 本轮只做验收，未修改产品代码、提示或索引。源代码散列与索引内容指纹保存在运行记录中；结束后再次核对源代码未变。

## 优先处理的两个问题

### 1. 普通上下文装入会丢掉关键依据

两次握手题的第4条检索结果 `ch5_s5_9_p563` 已完整解释：过期连接请求延迟到达，会使服务器误建连接并浪费资源，第三次确认可避免这种情况。但实际上下文依次装入握手流程、HTTP开销等片段后预算耗尽，这条关键结果没有进入输入。模型随后如实表示证据不足。

最早失败点是上下文选择，不应通过要求模型自行补充来掩盖。下一步用保存的Top-5结果离线比较上下文选择方案，重点检查是否保留问题所需的解释，同时检查其他14题的证据是否受损。通过后再复测受影响题，不必立即扩大模型或重建索引。

### 2. 生成会把补充解释写成教材事实

最明确的例子是KMP：资料2说三次比较“不必进行”，答案却说“三次比较都必然失败”。其中已知主串字符a与模式首字符a相等，省略的比较并非一定失败。DFS题还给出了输入未提供的具体DFS序列，并引用只有BFS序列的资料2。

总线、RISC、UDP等题还出现从限定场景推广成通则的情况。这些应作为生成阶段的回归样例；不宜仅靠“引用编号都存在”宣布通过，也不宜以新的教材硬编码规则代替一般的答案依据问题。
