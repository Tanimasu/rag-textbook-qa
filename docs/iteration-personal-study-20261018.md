# 个人学习工作流可靠性验收 · 2026-10-18

本轮从上次的 0.3.10 继续优化，当前版本 **0.3.25**，功能提交为 `1fad2da`。
分支仍为 `codex/history-favorites-20261017`；改动保存在本地，没有推送或触发远端 CI。
本轮重点是让历史、笔记、复习和导入在失败、跨标签页、跨服务进程时保持正确状态。

## 使用上有哪些变化

| 场景 | 现在的行为 |
| --- | --- |
| 问答、笔记、自评或备份已经写入，但列表读取暂时失败 | 按已提交结果显示；笔记可继续编辑，自评只记一次，恢复不要求重做 |
| 另一标签页保存、收藏或修改笔记 | 自动读取更新；当前问题和笔记草稿不被替换，答案返回期间延后同步 |
| 当前按钮尚未同步到另一页的收藏状态 | 按用户看到的“收藏 / 取消收藏”意图设置，同时保留最新笔记和复习信息 |
| 另一页删除正在编辑的问答 | 保留当前草稿及原问答供导出，明确显示仅在本页暂存，不重新创建已删除记录 |
| 已删除记录还有未导出的非空草稿 | 切换、清空、关闭或结束复习前可以取消；浏览器支持时刷新也会提醒，正常记录不增加确认 |
| 复习中切换历史、删除或取消收藏 | 不给错误的问题计分；发现记录刚被删除时保留正在编辑的草稿 |
| 晚上选择明天或一周后复习 | 从目标本地日期零点起到期；包含跨夏令时检查 |
| 用键盘复习和查看历史 | 焦点跟随当前问题或答案，结束后回到保留草稿的提问框 |
| 多个本地服务共用导入目录 | 识别真正运行的任务，重复请求不再次建立，运行中不能清理副本 |
| 列表读取时另一服务清理导入副本 | 跳过恰好消失的目录，其余任务仍可读取 |
| 导入启动或完成进度写盘失败 | 启动失败可重试；已发布的索引不误报失败，存储恢复后补写进度 |
| 恢复矛盾的备份记录 | 整批拒绝，不修改现有历史；旧版空回答继续兼容 |
| 备份组件加载失败、清空访问口令 | 提示明确；历史与逐题导出仍可用，已清空的口令刷新后不复现 |

详细说明见 [历史与收藏](history-and-favorites.md)、[复习](favorite-review.md)、[本机导入](textbook-import.md)
和 [版本记录](release-notes.md)。日常仍以 `rag-qa serve` 启动，无新增运行依赖。

## 两类完整流程

`scripts/check_study_workflow.py` 使用真实页面、HTTP 服务和临时 Chroma，Embedding、重排与生成均注入本地模拟器。
依次完成导入预览和确认、索引发布、流式问答、原文对照、笔记、收藏复习、Markdown / JSON 导出、五阶段检索观察，
并检查应用生成额度用完后仍可导出检索资料、清理副本后仍可阅读已发布索引。

默认资料是明确标注的合成片段，可在全新仓库及 CI 运行。
实际资料模式只读取操作系统教材的三个片段，原文件前后散列一致，原教材及已有索引不覆盖。
这里的每日生成上限是应用测试设置，与 Codex 账户额度不同。

`scripts/check_import_coordination.py` 启动两个独立服务进程，共用临时导入目录和索引。
服务 A 被阻塞在模拟向量化阶段时，服务 B 仍识别它正在运行；重复启动没有产生第二次建索引，清理返回 409，
临时索引没有作为可用教材暴露。发布后 B 能读取并检索，清理完成的副本后 A、B 都能继续读取。
两个进程正常退出；实际计数为 A 建索引一次、文档向量化一批，B 建索引零次、查询向量化一批，均为模拟调用。

复跑命令和所需依赖见 [开发说明](development.md)。输出必须使用新目录，避免覆盖旧证据。
两项流程已加入 CI 配置，本轮只在本机执行，没有触发远端 CI。

## 一项小的开销优化

没有搜索关键词时，不再为每条历史拼接完整回答和引用。未引入额外正文缓存，也没有改变匹配规则。
在同机 Chrome 的 1200 条合成记录上，每条含 4960 字符回答和 5760 字符引用，各查询取五次样本：

| 同步输入处理 | 优化前中位数 | 优化后中位数 |
| --- | ---: | ---: |
| 空查询 | 6.9 ms | 0.3 ms |
| 单关键词 | 6.5 ms | 6.7 ms |
| 无匹配关键词 | 7.4 ms | 7.4 ms |

匹配结果一致。这仅是本机输入事件处理诊断，不包含绘制、存储读取、网络或模型推理，不能据此声称整体问答提速。
