## 历史回答的模型阅读记录

以下是 Codex 对已有回答与教材审核行段的阅读，不是独立人工标注，也不作为调参样本：

1. **核心答案与扩展解释要分开复核。** 位示图、子网掩码、折半查找、AVL、参照完整性等回答
   可以直接对应关键答案要点；这不代表每条扩展陈述和每个引用编号均已核验。
2. **透明传输题遗漏一个明确要点。** `candidate-v1-08` 回答解释了转义与 PPP 字节填充，
   但没有明确说明 ESC 本身出现时再插入 ESC、接收连续两个 ESC 时删除前一个。
   该要点出现在冻结答案和教材审核行段中。已有上下文缺失，无法仅凭该导出判断遗漏首先发生在
   检索还是生成；历史证据审计另记录了相邻答案片段未进入检索结果的问题。
3. **扩展细节尚需实际上下文。** 磁盘回答加入 ECC、4 KB 与 LBA 等细节，停止等待回答追加 TCP
   的一般说明。部分内容未见于当前审核行段，不能据此认定完整生成资料中也没有，更不能只靠
   事实常识认定引用有依据。保留为待复核，不补造无依据标签。

下一轮质量验收应同时保留完整答案、结束状态、实际上下文和资料身份，才能将问题分到证据召回、
上下文装载、答案覆盖与错误引用等具体阶段。

## 单引擎连续 BM25 资源观察

在提交 `74f6d19` 的索引副本上，固定一个引擎，35 道 dev 问题分别搜索五本教材，重复 100 轮，
共 17,500 次 `search_bm25`；每轮另读取目录。embedding provider 被替换为一调用即报错的
观察桩，LLM 与 reranker 关闭，因此零模型调用；这不是 HTTP 或 CUDA 验收。
175 个问题 / 教材组合的分块身份与正文哈希在全部重复中一致，原索引版本未变。

计时循环约 252.7 秒。预热后 RSS 367.3 MiB，最后 50 轮范围为 298.9–300.1 MiB，
第 100 轮 299.5 MiB，关闭引擎后 232.1 MiB、清理副本后 231.2 MiB。
运行中描述符为 32–33，关闭后为 6；引擎、客户端、分词器三个弱引用均不再存活。
tracemalloc 从预热后约 6.6 KB 增至最后约 141.2 KB，其中观察报告、排名哈希等也保留在进程中；
不能把全部增量归到业务对象。该追踪不覆盖全部原生分配。

本轮没有观察到持续 BM25 请求下 RSS 随请求单调增长；此前反复创建 / 关闭引擎时的增长仍未归因。
它也不覆盖向量检索、模型推理、HTTP、Worker 或 GPU 内存，不据此宣布没有泄漏。
未修改生产内存管理、缓存大小或启动方式。

## Windows 导出哈希回归

提交 `74f6d19` 的 Linux、macOS、Chromium 和构建检查通过；两个 Python 版本的 Windows 测试
都在新增模板哈希断言失败。日志确认：模板哈希按 UTF-8 / LF 字节计算，而 Windows 文本写入
默认转换为 CRLF，导致实际文件的 SHA-256 不一致。不是教材或答案内容改变。

现在三个导出文件明确使用 LF，离线一致性报告也采用 LF；保留原哈希断言。
本机 Python 3.11 / 3.12 各 488 项测试及 484 个子场景通过，Ruff 通过。
修复后的 Windows 验证由下一提交的 CI 单独确认，不把本机通过当作 Windows 通过。
