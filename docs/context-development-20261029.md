## 2. 逐主张引用复核：保留原引用

新增 `evaluation/claim_review.py` 和 `scripts/prepare_claim_review.py`。操作方法见 [逐主张引用复核](claim-review.md)。这是一个离线导出/导入校验入口，**没有增加自动语义判分器，也没有改变 v7 评判器或产品生成提示词。**

实际执行：

1. 从五组 10 月 11 日实验读取冻结 cases、实际请求和原始响应，导出 45 个计划样本。按 ordinal/case/arm/repeat 与请求哈希绑定，重复请求散列不会合并回答。
2. 保存原始回答、正文视图、条件/符号的原句跨度、组合/范围引用的原文与偏移、实际提示词、模型配置、结束状态、完整上下文和来源。45/45 个历史回答记录完整正常结束；这不是新候选生成成功数。
3. 新模板全部 pending。将上轮 Codex 模型阅读的 **16 份回答、33 条定向主张**装入独立复核副本，再校验它们的原句、原引用与逐字来源证据；没有补造新模型判定。29/45 份回答继续 pending，16 份为 targeted，没有任何一份被自动标为全量审完。

材料保存在 `claim-packet-final/packet.json`、`review.md`、`review-template.json`；已填副本为 `claim-review-v1.json`，最终绑定校验为 `claim-validation-final.json` / `.log`，含逐回答和逐主张记录。

工具分别保存 `context_support` 与 `citation_support`。这批定向主张中有 **6 条上下文有支持、指定引用却不支持**（Cache 副本/SRAM 一条、数据库非负余额五条），都保留原回答的错误引用，没有借别处的正确来源改判为引用支持。其余条件遗漏、时间定义错误等仍按原记录保留；这批标签不是随机抽样，不能换算为系统准确率。

导入校验实际覆盖：

- 原句必须绑定 `answer_body` 的精确跨度，条件/数值/符号摘录必须来自该跨度。
- 引用标记必须是同一原文段落中的实际标记，不能从别段、参考章节或代码示例借用。
- 上下文支持可引用全部实际来源；指定引用支持的摘录只能来自回答原引用的来源。没有引用/未知引用不能标为支持。
- 错源摘录、替换原文字段、重复样本/主张、陈旧 packet、歧义 JSON、缺失标签及覆盖旧输出会被拒绝。
- 缺失或截断回答保留缺失状态。pending、targeted 和完整拆分声明单独计数，不输出自动放行结论。

边界：同段多个引用与某一子句的语义关系、主张是否真正原子化、条件是否完整保留、审核者身份和盲审顺序，仍需阅读者负责。现有复核者为 Codex 模型、非盲审、非专家金标准。本轮没有进行当前评判器的独立语义校准。历史 v3 未通过的结论保持。
