## 离线方案与边界

固定上一轮15道开发题的Top-5检索结果、原始分块与2000字符预算，不改索引或检索参数。使用已有 `bge-reranker-base` 对连续原文段落窗口重排，不生成摘要，不拼造原文。

先后比较了700字符窗口、补足前后段落、450字符窗口，以及保留枚举列表和早期/现代对比段的版本。前三版存在关键说明或限定丢失，均未进入产品默认流程。第四版保留了检查的关键语句；握手题通过另一段完整说明覆盖了旧请求延迟、误建连接及资源浪费。

产品候选还限制每次最多80个候选、最多额外一次重排；表格、围栏代码、显示公式保持整体；已知教材冲突先检查，重排失败回到原流程。列表和年代对比规则只是保守启发式，不保证覆盖所有跨段依赖。候选实现及新增的8项测试保留在本地实验目录中，未作为新实验功能留在产品内。

## 具体收益与未通过项

- **握手题**：失效请求的异常过程完整进入资料3，回答恢复了服务器误建连接与资源浪费的核心说明。但模型额外写了“持续分配缓存、变量”等未由该条引用直接支持的细节，所以不判为严格依据全部通过。
- **DFS/BFS题**：没有再给出输入未提供的具体DFS顶点序列，核心对比可用。
- **3NF题**：删除了未提供的系主任具体案例，保留可能出现异常及分解代价的说明。
- **事务题新增问题**：核心转账解释仍在，但答案新增“避免脏读、不可重复读”等断言。所引资料2和其余实际输入均没有这些术语或机制，故从原先可用变为需要修正。这一变化不是选择器造成的：事务题两轮的实际上下文与完整提示词逐字相同（见下方复核），差异只可能来自采样。它说明模型会凭已有知识补充，但不能算作候选方案的回归。
- **其他生成问题仍在**：KMP把“不回溯”推成“每个字符最多比较一次”；总线、RISC等题仍会丢掉适用范围。

## 复核：两轮输入相同的题（2026-09-15）

事后逐题比较两轮实际发送给模型的输入：候选改变了15题中12题的上下文，01、06、13三题的上下文完全相同。对这三题，用基线上下文重新调用 `RAGEngine.build_prompt` 生成的提示词与候选轮保存的提示词逐字一致，模型、温度0.7与输出上限也相同。三题的审查结论为：01两轮均可用，06两轮均需修正，13由可用变为需修正。

所以本轮使用的切换门槛“原可用题不得出现新增失败”在单次采样下并不可靠：输入不变，结论也会翻转。能确定归因于选择器的仍只有握手题关键片段进入上下文；答案质量上的增减需要同一输入多次采样、按题比较比例后才能判断。
