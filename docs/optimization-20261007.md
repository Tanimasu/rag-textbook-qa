## 教材校验期间的服务响应

进一步复现了指定教材提问时的事件循环阻塞：REST / SSE 的异步处理函数直接读取同步目录，
其中 Chroma 原生调用和索引发布重试的等待会阻止其他协程运行。
新增回归检查在两条路线修复前均失败；目录读取移到 FastAPI 已有线程池后通过。
访问校验仍先执行，教材不存在仍在返回 SSE 响应前报 404，回答继续经过原有有界队列。

本机 Python 3.11 / 3.12 各 419 项测试通过，Ruff 通过。
真实回环 HTTP 检查刻意暂停目录读取，同时发送另一条空问题请求：
两条路线均能立即返回 422，解除目录等待后原请求均返回 200。
原有容量 3、8 请求中 3 个成功 / 5 个 503、排队断连释放、活跃取消持槽及线程峰值 1 均通过，
最终待处理数为 0、生成额度仍为 200。该检查使用受控无模型引擎，不能作为模型延迟结果。
完整结果为本地忽略文件 `artifacts/evaluations/serving-queue-20261007-catalog.json`；
`scripts/check_serving_queue.py` 已包含此场景供跨平台 CI 复核。

## 全库候选预算的实际耗时

使用原索引副本、已缓存的本地 BGE embedding / reranker，每本教材选第一道 dev 题，
共 5 题，各重复 3 次。每个设备内两条路线交替执行，推理批大小均为 32；
两种输入形状均先预热，不复用模型分数。语义与 BM25 检索池保持一致，
只在全局重排前将每本融合候选从前 15 个截为前 10 个，总量由 75 变为 50。

| 设备 | 重排候选 | 样本 | 中位耗时（秒） | P95（秒） |
|---|---:|---:|---:|---:|
| MPS | 75 | 15 | 2.014 | 2.161 |
| MPS | 50 | 15 | 1.491 | 1.634 |
| CPU | 75 | 15 | 4.967 | 5.445 |
| CPU | 50 | 15 | 3.659 | 3.982 |

同题同轮的 50 / 75 耗时比，中位数在 MPS / CPU 上分别为 0.732 / 0.731。
本次两种设备均约省 27%；P95 是小样本最近秩统计，不能作为生产 SLO。
两条路线每题均调用一次 embedding 和一次 reranker，实际重排数分别为 50 / 75。
两次进程峰值 RSS 分别约为 1310 / 3914 MiB，覆盖整次运行，不能用来比较两条路线的内存。

原始逐次结果、脚本和来源核对保存在本地忽略目录：
`artifacts/evaluations/candidate-budget-20261007/`。
`provenance.json` 核对了数据集、计时脚本和引擎源码哈希。
MPS 使用 `7dc1789`；CPU 在启动关闭修复编辑后、提交前开始，其源码哈希对应 `c14ee5f`。
这两个版本的引擎差异仅为失败启动时关闭索引。

## 候选损失与设备差异

此前完成的 35 道 dev 分数复用实验，只评价目标教材标题，其他教材没有相关性标注：

| 重排候选 | 目标教材标题 Recall@5 | MRR | nDCG@5 |
|---|---:|---:|---:|
| 25 | 0.886 | 0.774 | 0.611405 |
| 50 | 0.971 | 0.778 | 0.628712 |
| 75 | 0.971 | 0.778 | 0.628987 |

50 与 75 的 Recall / MRR 相同，nDCG 略低；完整前五名顺序仅 19/35 一致。
这些是开发集代理指标，不能证明答案质量或独立跨教材相关性不受损。
原始结果为 `serving-performance-20261004/candidate-budget-dev.json`。

本轮实际计时中，MPS 前五名有 12/15 次一致，差异集中在同一道题的三个重复；CPU 为 15/15。
针对该题另行核对候选和原始重排分数：`computer_organization/ch4_s4_5_p512`
在 CPU 的教材内融合排序中排第 10，在 MPS 上排第 11，因此只保留前 10 个时，MPS 会失去该候选。
两种设备共同候选的重排分数最大差约为 0.00000191。诊断记录为同目录的 `diagnose.json`。

这支持继续复核 50 候选方案的性能与质量取舍，尚不足以修改默认值。
本轮没有修改候选预算、模型、推理批大小或实验功能的默认配置，也未使用 holdout 调参。
