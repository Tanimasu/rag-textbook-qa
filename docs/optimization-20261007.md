## 全库候选预算的实际耗时

使用原索引副本、已缓存的本地 BGE embedding / reranker，每本教材选第一道 dev 题，
共 5 题，各重复 3 次。每个设备内两条路线交替执行，推理批大小均为 32；
两种输入形状均先预热，不复用模型分数。语义与 BM25 检索池保持一致，
只在全局重排前将每本融合候选从前 15 个截为前 10 个，总量由 75 变为 50。

| 设备 | 重排候选 | 样本 | 中位耗时（秒） | P95（秒） |
|---|---:|---:|---:|---:|
| MPS | 75 | 15 | 2.014 | 2.161 |
| MPS | 50 | 15 | 1.491 | 1.634 |
| CPU | 75 | 15 | 4.967 | 5.445 |
| CPU | 50 | 15 | 3.659 | 3.982 |

同题同轮的 50 / 75 耗时比，中位数在 MPS / CPU 上分别为 0.732 / 0.731。
本次两种设备均约省 27%；P95 是小样本最近秩统计，不能作为生产 SLO。
两条路线每题均调用一次 embedding 和一次 reranker，实际重排数分别为 50 / 75。
两次进程峰值 RSS 分别约为 1310 / 3914 MiB，覆盖整次运行，不能用来比较两条路线的内存。

原始逐次结果、脚本和来源核对保存在本地忽略目录：
`artifacts/evaluations/candidate-budget-20261007/`。
`provenance.json` 核对了数据集、计时脚本和引擎源码哈希。
MPS 使用 `7dc1789`；CPU 在启动关闭修复编辑后、提交前开始，其源码哈希对应 `c14ee5f`。
这两个版本的引擎差异仅为失败启动时关闭索引。

## 本地模型的真实 HTTP 验收

新增可复跑的 `scripts/benchmark_serving.py`，使用缓存模型和临时索引副本，关闭 LLM / HyDE。
每本教材选第一道 dev 题，共 5 题，两轮交替发送单教材 / 全库请求，每种路线 10 个计时样本。
单教材与全库形状均先预热，HTTP 计时包含本机请求往返与队列等待，不复用推理结果。
应用源码为 `a1b155e`；报告包含运行脚本和应用源码哈希，现已逐项核对一致。
实际环境是 Python 3.11.15、torch 2.13.0、sentence-transformers 5.7.0、Chroma 1.5.9、
FastAPI 0.141.1、Uvicorn 0.52.3。这个缓存模型环境与 CI 的无模型环境分开记录。

| 设备 | 路线 | 样本 | HTTP 中位耗时（秒） | P95（秒） |
|---|---|---:|---:|---:|
| MPS | 单教材 | 10 | 0.554 | 0.585 |
| MPS | 全库 | 10 | 1.954 | 2.095 |
| CPU | 单教材 | 10 | 1.341 | 1.502 |
| CPU | 全库 | 10 | 4.905 | 5.278 |

这描述当前默认 75 候选的本机小样本，不是生产 SLO，也不是修改前后的提速比较。
八个客户端同时发出真实全库请求，容量设为 3：两个设备均有 3 个 200、5 个 503，
执行中引擎峰值均为 1。后两名的实际排队时间分别约为 MPS 2.095 / 4.038 秒、CPU 4.755 / 8.890 秒。

SSE 测试在真实重排开始后关闭排队请求，再关闭活跃请求并发送后续请求：排队断连没有启动引擎，
后续请求等待前一次原生推理退出、归还执行槽后才开始。活跃取消至归还执行槽分别约为
MPS 1.900 秒、CPU 4.763 秒。原生模型调用没有被中途强制停止；取消语义是丢弃结果并安全释放资源。
后续请求均恢复为 200，最终执行 / 排队数均为 0，生成额度均为 200。

| 设备 | 预热后 RSS（MiB） | 顺序请求后 | 并发请求后 | 取消恢复后 |
|---|---:|---:|---:|---:|
| MPS | 819.8 | 986.0 | 999.7 | 1011.7 |
| CPU | 3364.8 | 3364.6 | 3434.7 | 3572.1 |

RSS 来自系统 `ps`，包含模型和服务整个进程，不含设备内存。这些采样点不能证明没有泄漏，
也不能用于比较单教材与全库的内存。第一次 MPS 运行在预热后因诊断依赖缺失退出；
改用系统 RSS 后另存 `mps-v2.json`，保留原 `mps.json` 的 `complete=false`，未混入成功样本。
成功原始报告为 `artifacts/evaluations/local-http-20261007/{mps-v2,cpu}.json`。

## 50 / 75 候选的正文差异复核

新增无模型脚本 `scripts/audit_candidate_budget.py`，核对原 dev 数据集哈希与保存报告，
只读取版本一致的索引副本。导出所有 35 题的两份排名、共同候选位置、丢失 / 补入候选完整正文、
来源和正文 SHA256。19 题的排名与成员相同，16 题发生成员替换，共有 19 次丢失、19 次补入。
dev 题均没有已审核的正文证据跨度，因此正文覆盖率保持空值，不能从标题代理指标推导出来。
结果为 `artifacts/evaluations/candidate-budget-20261007/body-audit-v2.json`；
首版报告另行保留，第二版使用加强输入类型校验后的同一工具重新核对。

以下是 Codex 对 16 题替换正文的阅读记录，未赋相关性分数，不是独立人工评测。
“丢失”只表示退出前五名，不能据此断言剩余候选或最终打包上下文没有同一知识点。
编号对应报告中 dev 题顺序。

| 题号 / 主题 | 75 → 50 的正文变化 | 需要关注的范围 |
|---|---|---|
| 5 打印任务 | 打印机独占与互斥访问 → 存储芯片读写信号互斥 | 补入段落的“不会混乱”属于其他硬件语境 |
| 6 树形目录 | 数据库层次模型优缺点 → 两级文件目录效率、命名与隔离 | 补入段落更接近文件目录，但不直接解释任意树形层次 |
| 7 文件共享 | 符号链接共享与网络链接 → 操作系统主要功能概述 | 共享机制的具体说明减少 |
| 11 总线 | 系统总线连接 CPU、主存和 I/O → CPU 内部数据通路 | 系统级连接说明被内部路径说明替代 |
| 13 浮点数 | 浮点表示范围与溢出 → 定点小数格式 | 浮点数扩大范围的直接说明退出前五名 |
| 16 CIDR | 子网划分与主机数量取舍 → CIDR 最长前缀查找 | 两段分别偏子网背景和路由实现，均需结合其余候选 |
| 17 UDP | 实时数据的重传时延与丢失容忍 → TCP 基本特点 | 失去一段直接解释实时应用为何选择 UDP 的正文 |
| 23 循环队列 | 栈 / 队列存储比较与循环队列 → 变形补码的算术溢出 | 相同“溢出”措辞来自不同问题 |
| 27 DFS / BFS | 栈 / 队列、先序 / 层次的对照 → 图遍历和 visited 概述 | 对照解释减少，背景说明增加 |
| 28 哈希查找 | 哈希冲突探测的优缺点 → 哈希文件的键到地址映射 | 补入跨教材正文可能提供有效类比，标题零分不能代表无用 |
| 30 3NF | 三段规范化案例与分解步骤 → 3NF 缺点、规范化小结与概述 | 范围重组，不能只按替换数量判定损失 |
| 31 E-R | 全局 E-R 优化和需求确认 → 实体 / 联系到关系模式的转换 | 前后分别覆盖问题不同部分 |
| 32 连接查询 | 优化器背景与 INNER JOIN 示例 → WHERE 比较运算与括号匹配 | 新增跨教材括号匹配与 SQL 连接语义无直接对应 |
| 33 视图 | 通过视图限制访问范围 → 创建视图的约束与示例 | 实际用途说明减少，使用细节增加 |
| 34 触发器 | 定时事件及与触发器的区别 → 行级触发器语法 | 语法更贴近触发器，业务场景说明仍需其余候选 |
| 35 主键 / 唯一索引 | UNIQUE 约束说明 → PRIMARY KEY 约束说明 | 比较两侧的证据范围改变 |

这些结果加强了保留 75 默认预算的依据：小样本速度收益已经观察到，但正文替换有实质变化，
尚未完成独立评分或回答级对照。跨教材哈希文件一例也显示目标教材标题代理会漏掉可能有用的证据。
没有修改预算、冻结数据或教材正文。

## 跨教材评分导入与报告

新增 `evaluation/crossbook.py` 和 `scripts/score_crossbook_review.py`。
以原始导出为固定参照，要求编辑副本，检查问题 / 候选编号、教材身份、正文与哈希、

完成状态要求全部评分、审核者和 UTC 时间；审核者身份为自报，工具不验证其身份或独立性。

原有 35 题、268 个候选已通过完整性检查，评分仍全部为空，未输出质量分数。
测试中的手算合成评分仅用于验证计算，不写入实际候选或冻结数据。
完成的导入副本才会生成候选池 nDCG、有效证据命中率、倒数排名和池内覆盖率对照，
有效证据阈值为 2 分。分母只使用已导出的候选并集；未入池片段仍是未知，不能称为全库 recall。
两条路线的前后顺序来自清单，报告保存原始三个输入文件的哈希以供复核。
